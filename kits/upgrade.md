# 升級既有的家 by tt

> **ver 3.0** ｜ 時間看盤點結果，通常 20–40 分鐘 ｜ 前提：**家已經有東西，但不是我們的九包結構**（規矩直接寫在 `CLAUDE.md`／`AGENTS.md` 裡、根目錄有 `daily/`、沒有 `core-rules.md`……）
> tt 是 Tim 派到你電腦裡的駐點 Agent 工程師。這一包不是從零開始——你已經有一個家，只是長得不太一樣。做完之後，你的家會跟九包系列走同一套結構，後面的包才接得上。

## 你可能遇過的問題

- 第一堂課自己先跟著別的教學或別的 AI 建了一個資料夾，現在發現跟同學的長得不一樣
- 規矩、日誌都手動寫過一些，但接下來的包一直提示「找不到 `core-rules.md`」
- 資料夾是有的，但進度表不見了，不知道自己算做到哪一步

## 做完你會有

- 一份 `core-rules.md`（本尊）＋ 兩個薄入口，你原本寫的規矩**一個字沒少**，只是搬了位置
- 你原本的日誌搬進 `memory/daily/`，內容不動
- 一份 `onboarding.md`，依你**現有的檔案**打勾，不是靠猜的
- 知道接下來第一個該做的包是哪一個，而且可以直接接下去

## Section A · 體檢報告與升級計畫（選項題）

**選項題的格式**：`RUNTIME=claude` → 用 AskUserQuestion；其他 → 純文字列「1. 2. 3.」，結尾寫「回我數字，或直接打字也可以」；每題 ≤ 4 個選項，推薦的放第一個並標（推薦）。

### A-1 體檢報告（講給他聽，白話、三欄，不要列一長串檔名）

> 看完了。你的家長這樣：
>
> **已經有的**
> - 一份規矩（寫在 `[CLAUDE.md 或 AGENTS.md]` 裡，大概 [N] 行，講了你是誰跟你的地雷）
> - [N] 篇日誌、放在 `[daily/ 或其他位置]`
>
> **做了一半的**
> - [依 0-4 盤點結果填，例如：有 `memory/` 但沒有摘要跟待辦]
>
> **還沒有的**
> - [依 0-4 盤點結果填，例如：全域沒接、工具、知識庫、招式都還沒有]
>
> 換算成九包的話，你等於做完了 [哪幾包]，[第一個沒做的包] 還沒開始。

### A-2 升級計畫（列出來，只列要動的）

**每一條寫「做什麼、為什麼、原檔會去哪」——寫成肯定句，不要寫成問句。** 檔名、標記、備份方式這些你已經決定好了，計畫只是把你的決定用他聽得懂的話講一遍，讓他判斷「要不要動我的東西」這件大方向。例子：

> 我建議做這幾件，做完你的家就跟九包系列同一個結構，後面的包才接得上：
>
> 1. **規矩搬家**：把 `[CLAUDE.md 或 AGENTS.md]` 裡的規矩原封不動搬進新的 `core-rules.md`，原本那份改成一行 `@core-rules.md`（或三行指令式入口），再補齊另一個平台的入口。原本的檔案先備份成 `.bak`。
>    為什麼：Codex 跟 Claude Code 讀不同檔名，規矩只留一份本尊，兩邊才不會各自長大。
> 2. **日誌搬家**：`[daily/ 或其他位置]` 整個搬進 `memory/daily/`，不改檔名。
>    為什麼：後面的包跟老師的平台都認 `memory/daily/`。
> 3. **補摘要跟待辦**：`memory/MEMORY.md`、`memory/todo.md`，內容從你的日誌整理出來。
> 4. **`knowledge/` schema 改名**（如果有這個狀況）：只有 `CLAUDE.md` 的改名成 `AGENTS.md`，再補一行 `CLAUDE.md`。
> 5. **建進度表 `onboarding.md`**：把已經做完的包打勾。
>
> 不動的：你的 `[他自己的資料夾，例如 notes/]` 我不搬，之後在規矩裡加一行索引就好。

### A-3 問他（選項題）

question：這幾條可以照做嗎？

1. **全部照做**（推薦）——照列的順序整理，做完我會列出動了什麼、備份在哪
2. **有幾條先不要動**——你說是哪幾條（講編號就好），其他照做
3. **先不要動，我自己看一下**——這次先停在這裡，不整理

**這一題只問「要不要動」，不要順便問他檔名、格式、要不要備份。** 他挑掉哪幾條就跳過那幾條，剩下的照你原本的做法做完。

選 2：請他講清楚哪幾條，在 `onboarding.md` 的「卡住的地方」記一行「他選擇保留 [什麼]」，其他條照走 Section B。
選 3：跟他說「沒問題，資料夾維持原樣，你想通了再說一聲」，記一行到「卡住的地方」，結束這一包，不寫任何檔案。

## Section B · 動手（照他點頭的順序做）

**他點完頭就一路做完，不要每一條再問一次。** 每搬完一樣，用一句話告訴他你剛做了什麼、為什麼要這樣（像老師講課，不是像客服請示）：「你的規矩我原封不動搬進 `core-rules.md` 了，原本那份改成一行指過去——**以後不管你開 Codex 還是 Claude Code，讀到的都是同一份，不會兩邊各長各的。**」

**每一條動手前備份**：改任何既有檔案前，先複製一份 `.bak` 在原位置。

**Mac**
```bash
cp "[要改的檔案]" "[要改的檔案].bak"
```
**Windows（PowerShell）**
```powershell
Copy-Item "[要改的檔案]" "[要改的檔案].bak"
```

- **規矩搬家**：`core-rules.md` 不存在就建；存在就把要併進去的內容接在後面，用 `<!-- 從 [原檔名] 併入 · [日期] -->` 標記。**一個字都不要改寫**——那是他的話。改完把原本的入口檔改薄（`CLAUDE.md` 一行 `@core-rules.md`；`AGENTS.md` 三行指令式，照第 01 包的寫法），另一個平台缺的入口就照樣補一份。
- **日誌搬家**：
  ```bash
  # Mac
  mkdir -p "[AGENT_HOME]/memory/daily" && mv "[AGENT_HOME]/daily/"*.md "[AGENT_HOME]/memory/daily/" 2>/dev/null
  ```
  ```powershell
  # Windows
  New-Item -ItemType Directory -Force -Path "[AGENT_HOME]\memory\daily" | Out-Null
  Move-Item "[AGENT_HOME]\daily\*.md" "[AGENT_HOME]\memory\daily\" -ErrorAction SilentlyContinue
  ```
  空掉的 `daily/` 留著也無妨，不確定就留，不要刪資料夾。
- **全域入口**：照第 02 包的做法補上；那兩個位置本來就有內容的，先備份、把內容唸給他聽、問要不要併進 `core-rules.md`，不要直接蓋掉。
- **`knowledge/` 的 schema**：只有 `CLAUDE.md` 的，改名 `AGENTS.md`，再放一行 `@AGENTS.md` 的 `CLAUDE.md`。
- **他自己的資料夾**：在 `core-rules.md` 最後面加一小節索引，例如 `| 我的筆記 | notes/ |`，資料夾本身不動、不改名、不合併。

備援：任何一步指令跑不了，就照那一條的內容手動列給他看，請他自己動手，回來跟你確認結果。

做完把改了什麼**列一次（三到五行）**，**附上備份檔的位置**，再進 Section C。

>
> 1. **規矩本尊**：`[AGENT_HOME]/core-rules.md`——打開看一眼，你原本寫的內容都在裡面
> 2. **進度表**：`[AGENT_HOME]/onboarding.md`——依你已經有的東西，**[哪幾包]算做完了**
> 3. **接下來**：**第一個沒打勾的包是 [NN・名字]**——[一句話說這包做什麼]

然後：

> 1. **現在就接下一包**（推薦）——我直接開始
> 2. 先到這裡，下次再說

選 1 就抓那一包的網址，從它的執行區開始照做，**不要把他已經做過的包再跑一次**。

## Section E · 完成清單（AI 自己跑，全綠才說整理好）

```bash
# Mac
H="[AGENT_HOME]"
ls "$H"/*.bak "$H"/**/*.bak 2>/dev/null | grep -q . && echo "✅ 備份檔存在" || echo "➖ 沒有備份檔（可能這次沒有需要覆蓋的既有檔案，屬正常）"
test -s "$H/core-rules.md" && echo "✅ core-rules.md 存在且非空" || echo "❌ core-rules.md"
[ "$(grep -c . "$H/CLAUDE.md" 2>/dev/null)" -le 3 ] && echo "✅ CLAUDE.md 是薄入口" || echo "❌ CLAUDE.md 還太厚，規矩可能沒搬乾淨"
test -f "$H/onboarding.md" && echo "✅ onboarding.md 存在" || echo "❌ onboarding.md"
```
```powershell
# Windows
$H = "[AGENT_HOME]"
if (Get-ChildItem "$H" -Recurse -Filter *.bak -ErrorAction SilentlyContinue) { "✅ 備份檔存在" } else { "➖ 沒有備份檔（可能這次沒有需要覆蓋的既有檔案，屬正常）" }
if ((Get-Item "$H\core-rules.md" -EA SilentlyContinue).Length -gt 0) { "✅ core-rules.md 存在且非空" } else { "❌ core-rules.md" }
if ((Get-Content "$H\CLAUDE.md" | Where-Object { $_ -match '\S' }).Count -le 3) { "✅ CLAUDE.md 是薄入口" } else { "❌ CLAUDE.md 還太厚，規矩可能沒搬乾淨" }
if (Test-Path "$H\onboarding.md") { "✅ onboarding.md 存在" } else { "❌ onboarding.md" }
```

## 不該做的事

- ❌ 刪任何他的檔案、改寫他的規矩內容
- ❌ 叫他換資料夾——他的家在哪就在哪，名字不是 `-agent` 也不改、不搬
- ❌ 沒列計畫就開始搬
- ❌ 為了「整齊」把他自己的分類資料夾改名或合併
- ❌ 沒有 `onboarding.md` 就結束這次對話（沒有它，下次又要盤點一次）

## 踩坑紀錄（給 Tim）

- **這一包的判斷是「以檔案為準」，不是「以他說的為準」。** 他常常記不清自己做到哪，靠 `ls` 一遍比問他準。
- **`.bak` 備份不是形式，是真的會被用到。** 合併規矩內容時如果順序搞錯、或誤刪了一段，`.bak` 是唯一救得回來的地方。
- **中文資料夾名、他自己的分類資料夾一律不動。** 這一包最大的風險是「順手幫他整齊」，那不是升級是重建，會讓他找不到東西。
- **升級完直接建議下一包，不要停在「整理完了」就結束。** 沒接下去的話，他隔天還是不知道該做什麼，升級這件事就白做了。

## 常見問題

- **「我原本的規矩會不會被改寫？」** 不會，原封不動搬進 `core-rules.md`，只有位置變了。
- **「我自己分類的資料夾會被搬走嗎？」** 不會，只在規則檔加一行索引告訴 AI 去哪找，資料夾本身不動。
- **「升級完是不是要重新做一次前面的包？」** 不用，做過的包依檔案打勾，直接從第一個沒做的包接下去。
- **「備份檔要留著嗎？」** 建議留著，確認整理後的內容都對了，之後想刪隨時可以刪。
