## Section A · 訪談（全部選擇題）

**選項題的格式**（每題都照這個）：
- `RUNTIME=claude` → 用 AskUserQuestion；其他 → 純文字列「1. 2. 3.」，結尾寫「回我數字，或直接打字也可以」
- 每題 ≤ 4 個選項，**推薦的放第一個並標（推薦）**，每個選項後面一句「選了會發生什麼」
- 最後一個選項永遠是「其他（我自己說）」
- 開放題要附「答不出來就選一個」的 fallback 選項
- 「要繼續嗎」一律兩個選項：「繼續（推薦）／先到這裡，下次再說」
- **每題他答完，先用一句話接住他再往下做**（不要只回「收到」）：把他的答案跟接下來要發生的事連起來，例如他說「想找可以馬上用在工作上的做法」→「那我整理的時候會把可執行的步驟往前排，理論的部分縮成一兩行。」

**A-2～A-4 這三題都是「他的事」，一定要問**——讀哪一份、為什麼讀、他自己怎麼看，這些你猜不到，而且第三題就是整個知識庫裡別人沒有的那一塊。**但 schema 怎麼寫、知識頁分哪幾區、健檢查哪六項，不要拿來問他。**

### A-1 先講方法論（不問問題，講完直接進 A-2）

> 接下來這套做法叫 **LLM Wiki**，是 Andrej Karpathy 提出來的——他是 OpenAI 創始成員、Tesla 前 AI 總監。
>
> 核心想法很簡單：**不要每次都叫 AI 去翻原始文件，而是讓它把讀過的東西整理成一個會長大的知識庫。**

三層講清楚：

> | 層 | 在哪 | 放什麼 | 誰動它 |
> |---|---|---|---|
> | **① 原料** | `raw/` | PDF、逐字稿、文章 | 你丟進來，**我只讀不改** |
> | **② 知識** | `knowledge/` | 我整理出來的知識，互相有連結 | 我寫、我維護 |
> | **③ 規格** | `knowledge/AGENTS.md` | **定義這個知識庫怎麼組織** | 你我一起維護 |

**第三層最容易被跳過，但少了它整套不會運轉**——一定要講：

> 第三層叫 **schema**，就是**知識庫自己的規則檔**。
>
> 它規定：一頁筆記長什麼樣、要有哪幾個區塊、什麼東西該建新頁什麼該併進舊頁、
> 多久沒動要標成過期。
>
> **沒有它，我每次整理的格式都不一樣**——三個月後你打開，會發現前後兩百頁根本不像同一個人寫的。

**然後把它跟規則檔那件事扣起來**（他已經學過這個概念了）：

> 而且這個東西你已經見過了。**還記得「全域規矩」跟「專案規矩」嗎？**
>
> `knowledge/AGENTS.md` 就是**專案規矩**——只是這個「專案」是你的知識庫。
> 它會疊在 `core-rules.md` 上面：我在知識庫裡做事的時候，同時知道「你是誰」跟「這個知識庫怎麼維護」。
>
> **你以後每開一個 `projects/` 底下的資料夾，都是同一招。**

三個動作：

> - **放進來**（Ingest）— 你丟一份東西，我讀完，更新相關的筆記，建立彼此的連結
> - **問問題**（Query）— 你問，我從整理過的知識回答，附上出處。**好的答案我會存回知識庫**
> - **定期健檢**（Lint）— 我檢查有沒有互相矛盾、過期的說法、沒人連到的孤兒筆記

> 跟一般用法最大的差別：**知識庫會越用越厚，不是每次從零開始。**

**然後講兩件他一定會撞到的事，先講比事後解釋好**：

> **① 這件事會花錢。** 讀一份 PDF、整理成筆記、建立連結——這是我做的所有事情裡最耗用量的。
> 所以不要一次丟二十份進來，**一次一份，做完看一眼再決定下一份。**
>
> **② 不是每種檔案我都讀得動。** 純文字、Markdown、網頁最順；PDF 看它怎麼做的，
> 掃描的圖片檔我讀不出字；Word、Excel、簡報有時候要另外裝工具才解得開。
>
> **我讀不動的時候會直接說，然後告訴你要裝什麼。** 那不是壞掉，是缺工具——
> 有一包專門在裝工具，裝完 PDF、Word、簡報會先轉成純文字再給我。

### A-2 第一題：第一份原料用哪個

- header：第一份原料
- question：知識庫現在是空的。第一份要讀什麼？
- options：
  1. **這門課第一堂的回顧（推薦）**——老師寫的，讀完你的分身就是一個「懂這門課」的 Agent，你問它「全域跟專案差在哪」它答得出來，而且用課堂上的講法
  2. **我自己帶的一份**——我貼路徑或把檔案拖進來（PDF、文章、報告都行）
  3. **一篇我想讀的網址**——想讀但一直沒空讀的長文，我貼網址
  4. 其他（我自己說）

選 2 或 3：**照他的做**，收料三問一樣要問，課堂回顧那份可以之後再收。
他沒上過這門課、手邊也沒東西，直接建議走選項 3。

### A-3 第二題：你為什麼想讀它

- header：你想拿到什麼
- question：你為什麼想讀它？想從它拿到什麼？
- options（他可以直接打字，這些只是給他一個起點）：
  1. **想搞懂整套怎麼運作（推薦）**——之後我回答你問題，會優先用「架構」的角度講
  2. **想找可以馬上用在工作上的做法**——我整理時會偏重可執行的步驟
  3. **想記住重點，之後查得到就好**——我整理得精簡，重點是好查
  4. 其他（我自己說）

他的答案**用他自己的話記下來**，等一下要原樣寫進知識頁的「為什麼讀這個」。

### A-4 第三題：你自己已經有的想法

**這一題最重要，他講什麼逐字記下來，不要改寫成書面語。**

- header：你的看法
- question：你自己已經有的想法——你覺得哪裡最有用、哪裡還是不懂？就算只有一句「我覺得這個講得太理想化」也算
- options：
  1. **我有想法，我直接說（推薦）**——你講，我一個字不改地記下來
  2. **我覺得某個地方最有用**——講哪一個就好，我補上下文
  3. **我還有地方沒搞懂**——講哪裡卡住，我在知識頁裡標起來
  4. **我還沒有想法，先記「待補」**——我先寫「待補」，你之後想到隨時叫我補上去

**跟他講一句為什麼問這題**：

> 第三點最重要。**你的看法才是別人沒有的那部分。**「內容重點」誰都查得到，「你的看法」只有你有。

### A-5 中場確認

> 2. 先到這裡，下次再說

### B-4 整理成一頁知識

**這一步順便教他分類的概念。**

> 我要把整理好的東西放進 `knowledge/topics/`——這是「主題」的分類。
>
> 為什麼要分類？因為知識庫會長大。**你之後會有 topics（主題）、people（人）、projects（專案）這些分類**，找東西才找得到。
>
> 今天先開 topics 這一個，其他等你有內容再開。

照 **Section C-3** 寫那一頁，**六區格式一個都不能少**。

### B-5 自問自答三題（不是考他）

寫完，**用課堂上的講法自己問自己三題，答案直接寫出來給他看**：

> 我拿這頁知識問我自己三題，答案我直接寫給你看：
>
> 1. **全域規矩跟專案規矩差在哪？** ——全域是「你是誰」，任何資料夾都生效；專案規矩只在那個資料夾生效，兩層是疊起來的
> 2. **為什麼規則檔不能一直長大？** ——它每次開場都會被全部讀進來，塞太多就變慢、變貴，而且重點被淹掉
> 3. **知識為什麼要放在規則檔外面？** ——因為知識是「要用才查」的那一層，放外面它才可以無限長大
>
> 這樣講你同意嗎？

- header：這樣講對嗎
- options：
  1. **同意（推薦）**——那這頁知識是對的，我們往下走
  2. **哪裡不對我說**——你講哪一句怪，我改那一頁
  3. 其他（我自己說）

他說哪裡不對，就改知識頁，**不要辯**。

### B-6 現在示範一次健檢

**知識庫現在只有一兩頁，查起來很快——刻意的，讓他先看清楚健檢長什麼樣。**

先講為什麼：

> 知識庫最大的問題不是「沒東西」，是**爛掉了沒人發現**——筆記互相矛盾、寫了一半沒接完、去年的說法還擺在那裡當真的。
>
> 你不會發現，因為你不會沒事去翻。**所以要我定期檢查。**

照這六項查一遍，一項一項報：

| 查什麼 | 怎麼查 | 找到了怎麼辦 |
|---|---|---|
| **記憶檔沒跟上** | `memory/MEMORY.md` 的日期距今超過 **7 天** | **當場用日誌補到最新**，然後告訴他一句。這台還沒有記憶檔就報「跳過」 |
| **孤兒頁面** | `knowledge/` 裡沒有被任何頁面連到的 | 補上連結，或問他還要不要留 |
| **知識缺口** | 有連結指過去、但那一頁不存在 | 列給他看，問要不要補 |
| **過時內容** | 超過 **60 天**沒動過的頁面 | 標出來，問他還算不算數 |
| **重複頁面** | 兩頁在講同一件事 | 建議合併，他點頭再動 |
| **raw 裡有沒讀的** | `raw/` 有檔案，但 `knowledge/` 沒有對應的筆記 | 列給他看，問要不要現在讀 |

第一項最重要，**要特別跟他講**：

> 這六項裡面，**第一項是最會出事的**。
>
> 記憶檔是我每次上工唯一一定會讀的檔案。它停在哪一天，**我對你的認知就停在哪一天**——你以為我記得，其實我停在三個月前。
>
> 而且它壞掉的時候不會報錯，只會讓我慢慢變笨。所以每次健檢，這一項先查。

報完給他一句結論：

> 健檢完成。現在只有 [N] 頁，還很乾淨——**但它會長大**，所以我把這件事寫成規矩。

然後照 **Section C-4** 把健檢六項寫進 `core-rules.md`。

## Section C · 動手寫，邊做邊教（不要問他要不要調整）

**這是你的專業判斷，不是他的選擇題。** schema 長什麼樣、知識頁分哪幾區、健檢查哪六項，這份劇本已經幫你想好了——**直接寫，同時用一兩句話教他為什麼**，不要把內容列出來再讓他選「照做／調整」，他多半答不出來、只會卡住。**他的原話（A-3、A-4）照抄不改**，那部分本來就是他的。

- 先 `Read` 目標檔。**存在就疊加**，不存在才建。**只有這一步會蓋掉他自己寫過的內容，才先給他看一眼**（C-2 的舊版 schema 就是這種）；純粹是你新建的東西，做完直接秀成果（Section D）。
- 寫進 `core-rules.md` 的段落包在標記裡：
  ```markdown
  <!-- tt:kit-05 START -->
  …
  <!-- tt:kit-05 END -->
  ```
  重跑這一包時，只替換標記之間的內容；標記外面一個字都不動。

### C-1 `[AGENT_HOME]/knowledge/AGENTS.md`（schema 本尊）

**直接寫，格式不用問他。`knowledge/AGENTS.md` 已存在就只補缺的段落，不整份覆蓋**——他可能已經加過自己的分類或規矩，那一段是他的，不要動。

```markdown
# 這個知識庫怎麼維護

> 這是知識庫自己的規則檔（Karpathy 三層裡的第三層 schema）。
> 它疊在 `core-rules.md` 上面——那份說我是誰，這份說這個知識庫怎麼組織。

## 三層

| 層 | 位置 | 規則 |
|---|---|---|
| 原料 | `../raw/` | 只進不改。原始檔案不要動、不要刪 |
| 知識 | 本資料夾 | 我整理的頁面，彼此用 `[[連結]]` 串起來 |
| 規格 | 本檔案 | 定義下面這些規則 |

## 一頁筆記長什麼樣

每一頁都要有這幾區，順序固定：

- **frontmatter**：`來源`、`讀於`（日期）
- **為什麼讀這個**：他的原話，不要改寫
- **內容重點**：我整理的
- **他的看法**：他的原話，**逐字保留**——這是別人沒有的部分
- **我補充的**：我讀完發現、他沒提到的
- **連到**：`[[相關頁面]]`

## 什麼時候建新頁、什麼時候併進舊頁

- 這個主題**已經有頁** → 併進去，在「內容重點」加一段，註明日期
- 是**新主題**，而且之後還會再碰到 → 建新頁
- 只是一次性的雜訊 → 不建頁，寫進當天的日誌就好

## 分類

- `people/` — 人物
- `topics/` — 主題知識
- `projects/` — 綁特定案子的知識

放不進這三類就先放根目錄，等同類的東西多了再開資料夾。**不要為了分類而分類。**

## 定期健檢

六項：記憶檔沒跟上（`memory/MEMORY.md` 超過 7 天）、孤兒頁面、知識缺口、過時內容（60 天）、重複頁面、`raw/` 裡有沒讀的。做法寫在 `core-rules.md` 的「定期健檢」那一節。
```

**檔名為什麼是 `AGENTS.md`**：子資料夾裡的規矩，Codex 讀 `AGENTS.md`、Claude Code 讀 `CLAUDE.md`。跟根目錄一樣的做法——**一份本尊、一個薄入口**，不用 symlink：本尊叫 `AGENTS.md`（這是跨 Agent 的開放標準檔名），旁邊放一個一行的 `CLAUDE.md`，Claude Code 開場會自動把它展開。他只用 Codex 也照放，多一個一行的檔不礙事，哪天換工具不用重做。

## 踩坑紀錄（給 Tim）

- **schema 一定要在第一頁知識之前建**。順序反過來，第一頁就會長成隨手寫的樣子，之後每一頁都在遷就它。
- **Obsidian 移到回家裝**。課堂上裝它只會看到一張白紙，還吃掉十分鐘。記進待辦、往下走。
- **健檢第一項排在最前面是刻意的**。記憶檔壞掉不會報錯，只會讓 Agent 慢慢變笨；它排第二第三就會被跳過。
- **「他的看法」允許填「待補」**。舊版逼他當場講出想法，講不出來的人會卡住整段；給一個「待補」的出口，流程不會停。
- **原料一次一份**。讀檔案是整趟最耗用量的動作，一次丟二十份會讓他第一次就對成本有陰影。

## 常見問題

**Q：我沒上過那門課，第一份要讀什麼？**
挑一篇你想讀但一直沒空讀的長文或網址，一樣走收料三問。內容是什麼不重要，**學會怎麼收**才重要。

**Q：`AGENTS.md` 跟 `CLAUDE.md` 為什麼要兩份？**
本尊只有一份（`AGENTS.md`，跨 Agent 的開放標準檔名），另一份只有一行 `@AGENTS.md`，是給 Claude Code 的入口。改規矩永遠只改本尊。

**Q：PDF 讀不動怎麼辦？**
掃描成圖片的 PDF 沒有文字可讀，我會直接跟你說。裝工具那一包裝完 markitdown 之後，PDF、Word、簡報會先轉成純文字再進來。

**Q：知識頁要寫多長？**
「內容重點」用條列，不要整份重抄——重抄的話你不如直接讀原檔。真正值錢的是「他的看法」跟「我補充的」那兩區。

**Q：健檢多久跑一次？**
每個月一次，或你說「健檢一下」。頁數少的時候幾秒就跑完，養成習慣比跑得勤重要。
