> tt 是 Tim 派到你電腦裡的駐點 Agent 工程師。這一包做完，你的分身碰得到你電腦以外的東西，而且你做過一次的事，以後一句話就能重跑。

## 你可能遇過的問題

- 你丟一支 YouTube 網址給 AI，它跟你說它打不開、請你把內容貼給它
- 每次要它整理東西，格式、長度、要不要做成網頁，你都得從頭交代一遍
- 筆記明明就在 Obsidian 裡，但要它讀，你還得一個一個把路徑貼給它

## 做完你會有

- **兩把鑰匙**：YouTube 逐字稿、Obsidian 知識庫——跑一次清單指令就看得到
- **一條你自己的流程**：`workflows/video-summary.md`，說「摘要這支」它整套自己跑完
- **一個招式**：同一套步驟包進 `skills/`，變成它自己判斷什麼時候該用
- **一頁打得開的成品**：`projects/practice/` 底下的 HTML 摘要
- **一張鑰匙地圖**：三種鑰匙、四種通道，以後要接任何東西，先問哪兩句

## Section B · 動手

### B-1 先讓他知道現在的限制

> 到目前為止，我只能碰到你電腦裡的檔案（前面幾包裝的工具也都只在你電腦裡）。
>
> 你如果叫我「幫我看這支 YouTube 影片講什麼」，我做不到——**我沒有那扇門的鑰匙**。
>
> 接下來我幫你裝第一把鑰匙。

（講完照 A-1 那段預告直接動手，不要停下來等他同意。）

### B-2 裝 YouTube MCP

**選這個當第一把，因為它不用註冊、不用申請金鑰，而且效果馬上看得到。**

要裝的套件：`@kimtaeyoon83/mcp-server-youtube-transcript`（靠 yt-dlp 抓字幕，不需要 API key）。

看他用哪個平台，直接執行對應的指令，不用等他回話。

**Claude Code**

```bash
claude mcp add --scope user youtube-transcript -- npx -y @kimtaeyoon83/mcp-server-youtube-transcript
```

`--scope user` 是關鍵——**加了它才會在他所有資料夾都生效**，不然只有現在這個資料夾有。

**Codex**

```bash
codex mcp add youtube-transcript -- npx -y @kimtaeyoon83/mcp-server-youtube-transcript
```

**裝完你自己驗**（不要叫他去別的對話測）：

```bash
claude mcp list      # Claude Code
codex mcp list       # Codex
```

看到 `youtube-transcript` 就成功了。第一次可能顯示 `Failed to connect`，那是 npx 還在下載套件，等十幾秒再跑一次。

**備援：指令跑不動的時候**

**不要卡在這裡，也不要跟他說做不到。** 改成手動貼設定——你把內容印出來，請他複製貼上。

先告訴他要開哪個檔案：

- **Claude Code**：`~/.claude.json`（Windows 是 `C:\Users\你的名字\.claude.json`）
- **Codex**：`~/.codex/config.toml`（Windows 是 `C:\Users\你的名字\.codex\config.toml`）

然後給他要貼的內容——

Claude Code，貼進最外層的 `mcpServers` 裡面：

```json
"youtube-transcript": {
  "type": "stdio",
  "command": "npx",
  "args": ["-y", "@kimtaeyoon83/mcp-server-youtube-transcript"]
}
```

Codex，貼在檔案最後面：

```toml
[mcp_servers.youtube-transcript]
command = "npx"
args = ["-y", "@kimtaeyoon83/mcp-server-youtube-transcript"]
```

**如果他原本就有別的 MCP，提醒他 JSON 的逗號**——這是最常出錯的地方。不確定就請他把整個檔案貼給你，你幫他改好再貼回去。

**裝完一定要重開**——這是他要動手的一件事，四件事一次講完：

> **目標**：讓剛裝的鑰匙生效。MCP 要重開對話才會掛上來，像插上新的隨身碟要重新掛載。
>
> **步驟**：
> 1. 關掉這個對話
> 2. 新開一個對話
> 3. 一樣在 `[AGENT_HOME]` 這個資料夾開
> 4. 跟我說「裝好了」
>
> **回來說什麼**：一句「裝好了」就行，不用貼任何東西給我。
>
> **做不到怎麼辦**：如果重開之後我好像忘了我們在幹嘛，把這句貼給我就接得回來——「我在跑第 07 包，剛裝完 YouTube 鑰匙，接下去。」

他回來之後，**你自己再跑一次 `mcp list` 確認**，然後直接往下走。

**他卡住的時候：不要等他求救。** 看到他沒回應、說「找不到」「我不會」，主動說：

> 沒關係，這一步本來就有點技術。**你截個圖給我看**，我幫你看是卡在哪裡。

看得到畫面就直接告訴他點哪裡。

### B-3 讓他用一次

**裝完一定要馬上用，不然他不會知道這有什麼用。** 先問 A-2，拿到網址（或用你挑的範例）之後，讀出逐字稿，然後**做一件他自己做不到的事**：

> 這支影片 [長度]，我讀完了。重點是這三個：⋯⋯

**然後多做一步：轉成他讀得下去的樣子。** 這一步不能省，而且要講出理由——它是一個產品觀念，不只是排版。

> 不過我剛才那一大段，你讀起來累不累？
>
> **AI 的產出如果人讀不下去，等於沒產出。** 我幫你換個樣子。

把摘要輸出成**一頁 HTML**（單一檔案、內嵌樣式、可以直接用瀏覽器打開），存進 `[AGENT_HOME]/projects/practice/`（沒有就建），然後給他完整路徑叫他打開。

> 打開看看。同樣的內容，這樣是不是好讀很多？
>
> **格式本身就是體驗的一部分。** 以後你叫我整理東西，可以直接說「做成一頁 HTML 給我看」。

### B-4 教他什麼是 MCP

**用完再解釋，他才有體感。**

> 剛才那個東西叫 **MCP**。
>
> 你可以把它想成**鑰匙**——每裝一把，我就多能碰到一個地方。YouTube 是一把、你的筆記軟體是一把、公司的系統也可以是一把。
>
> **所以之後你想讓我用某個 app 的時候，先問我一句：「有沒有這個的 MCP？」**
>
> 我會去找。有的話我幫你裝，沒有的話我告訴你有什麼替代做法。

### B-5 把剛才那件事變成一條流程

**這一步才是這一包真正值錢的地方。裝工具人人會，把工具變成流程才是分身。**

> 你剛才那個動作——丟一支影片給我、我讀完、整理重點——**你以後大概還會做很多次吧？**
>
> 那我們就不要每次都重講一遍。我把它寫成一條流程，以後你只要說「摘要這支」，我就知道整套要怎麼做。

接著問 A-3、A-4、A-5，**一次一題**（這是他的流程，不是你的）。

**流程不要寫進規則檔——開一個 `workflows/`。** 這一步的做法本身就是一堂課，講給他聽：

> 我要把它寫成一個獨立的檔案，**不是加進你的規則檔**。
>
> 因為規則檔我每次開工都會整份讀完。流程只有你叫我做那件事的時候才需要——**每次都讀等於每次都在浪費**。所以流程放外面，我要用的時候才去翻。

檔案內容照 **Section C** 寫。寫完**當場再跑一次**，用剛才那支影片：

> 寫好了。我們試一次——你只要說「摘要這支」，看看是不是照你要的跑。

**講明白為什麼要這樣分**：

> 這就是**索引**的概念——規則檔只記「東西放哪」，不記東西本身。
>
> 你以後流程會越來越多，規則檔還是這麼薄。

**第 4、5 步現在有地方放了**：

> 你看流程最後兩步——存進 `raw/`、記進日誌。**這兩個地方前面幾包就建好了**，所以這條流程從頭到尾都跑得通。

### B-6 再升一級：把流程變成它自己認得的招式

**他第 06 包已經有第一招（daily-log）了，這裡是第二次做同一件事，可以快：**

> 剛才那條流程有個問題——**你要記得叫它。** 你得說「摘要這支」，我才會去翻 `workflows/`。
>
> 哪天你忘了有這條流程，它就等於不存在。
>
> 所以還有一層叫 **Skills**。同樣一套步驟，包成 Skill 之後，**變成我自己判斷什麼時候該用**——你只要說「我想學這個」，我就知道要跑哪一套。
>
> 這跟 daily-log 是同一招——**差別只在觸發條件**：那個是「收工」，這個是「丟一支影片給我」。

- **Claude Code** 有現成的工具：`/skill-creator`。帶他跑一次，把剛才那條「影片摘要」流程包成 Skill。
- **Codex** 沒有這個指令，就在 `skills/` 底下建一個資料夾、寫一份說明檔（內容見 Section C），開頭寫清楚**什麼情況要用這個 skill**——那一行就是觸發條件。

**順便點一句**：Skill 有四種——流程型（剛才這個）、視角型、規範型、工具型。前面包講過，這裡只要指出「你現在做的是流程型」。

**提醒他一件重要的事**：

> 不要急著收集別人的 skill。**你自己做過一次、覺得「怎麼又來了」的事，才值得包成招式。**
> 別人的方法先個人化，自己的做法才系統化。

### B-8 鑰匙有三種，通道有四種

**裝完兩把鑰匙，先講重點再講分類：**

> 你剛才裝的這兩把，是最便宜的兩種。**以後你要我接任何新東西，我心裡都先問兩句：是不是 Google 家的？我只要讀，還是也要寫？** 這兩個答案決定我怎麼接，你不用懂細節，但可以知道我在想什麼。
>
> 細看一下你剛才裝的：
>
> | 鑰匙 | 給我多大權 | 例子 |
> |---|---|---|
> | **免鑰匙** | 靠你本機的權限、你已經登入的狀態 | Obsidian、YouTube 字幕 |
> | **API Key** | 一把長期鑰匙，貼了就全開，要手動撤 | 資料庫、Notion |
> | **OAuth** | 限範圍、會過期、隨時撤——最安全 | Google 的東西、GitHub |
>
> 接的方式（通道）也有四種：**原廠內建的連接器 → MCP 轉接頭 → 命令列工具 → 直接幫你點畫面。** 越往後越自己來、越脆。
>
> Google 的個資（Gmail、雲端硬碟、行事曆）一律要 OAuth——有內建連接器就用連接器，不要自己貼鑰匙。

**規矩：**

> 能用 OAuth 就別到處貼 API Key；不用的鑰匙要撤；來路不明的 MCP 不要裝——它拿到的是你的授權。

## 踩坑紀錄（給 Tim）

- **YouTube 當第一把鑰匙**，是因為不用註冊、不用金鑰，裝完三分鐘就有體感；換成任何要申請 API Key 的，一半的人會卡在申請頁面。
- **`--scope user` 一定要寫**。少了它，他換個資料夾開對話就發現鑰匙不見了，會以為是壞掉。
- **裝完必用、用完必解釋**。先給體感再給名詞（MCP），順序反過來他只會記得一個縮寫。
- **流程寫 `workflows/` 不寫規則檔**，是這一包真正的教學點：規則檔是每次都讀的成本，流程是偶爾才用的資產。這條講清楚，他之後才不會把什麼都往規則檔塞。
- **Obsidian 那半允許跳過**。它依賴外部軟體安裝跟 Node 版本，是整份腳本最容易斷的一步；斷在這裡會連前面的成就感一起賠掉。

## 常見問題

**Q：`Failed to connect` 是不是裝壞了？**
多半只是 npx 還在下載套件。等十幾秒再查一次清單；連續三次都紅，才走手動貼設定的備援。

**Q：可以不重開對話嗎？**
不行。MCP 是對話啟動時掛載的，不重開就是看不到。

**Q：Obsidian MCP 說「不是 vault」？**
`knowledge/` 裡沒有 `.obsidian/`——代表他還沒真的用 Obsidian 開過那個資料夾。開一次就好了。

**Q：以後想接 Gmail、Google 日曆呢？**
那是 Google 的個資，走 OAuth 或原廠連接器，不要貼 API Key。跟他說一句「先問我有沒有現成的連接器」就好。

**Q：`workflows/` 跟 `skills/` 到底差在哪？**
流程是你叫它才跑，招式是它自己判斷該不該跑。同一套步驟，兩種觸發方式。
