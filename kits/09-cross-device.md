- 知道跨電腦最省事的做法：把整個 `AGENT_HOME` 放進雲端硬碟的**桌面同步版**（不是瀏覽器版）

- 一份可以選擇傳回給 Tim 的 `onboarding.md`，記著你們卡在哪幾步

## Section B · 動手

### B-1 先讓他看見為什麼

> 你的分身全部是純文字檔——這件事現在要派上用場了。
>
> 最省事的跨電腦做法：把整個 `[AGENT_HOME]` 放進**雲端硬碟的桌面同步版**（要裝應用程式讓它跟你的硬碟同步，不是打開瀏覽器上傳）。放進去之後，另一台電腦裝同一個雲端硬碟、資料夾同步下來，路徑就跟這台電腦幾乎一樣，你的分身就直接接上。

Q1 選「有，現在就搬」才往下做；選「沒有」跳到 B-4。

### B-2 先列計畫，他點頭才動

**先說一句人話，讓他知道我們現在要做什麼**：

> 好，我們現在要做一件事：**把你的分身搬到雲端硬碟裡**，這樣以後換電腦，它記得的東西不用重建一次。這一步會動到整個資料夾，我先講清楚怎麼搬，你聽得懂就放行。

**這一步會搬動整個資料夾，一定要先列計畫。** 用 0-4 掃到的雲端硬碟路徑，或問他要用哪一個（沒掃到就直接問：「你在用哪個雲端硬碟？Google 雲端硬碟／Dropbox／OneDrive／其他」）。

列給他看：

> 計畫是這樣：
> 1. 把 `[AGENT_HOME]` 整個搬到 `[目標路徑]/[資料夾名]`
> 2. 搬完把這台電腦的全域入口（第 02 包留的那兩行）改成指向新路徑
> 3. 搬之前不刪任何東西，原地搬移，不是複製一份
>
> 1. 照這個計畫做（推薦）
> 2. 我要指定別的路徑

**只問「要不要搬、搬去哪」這兩件——指令怎麼下、入口那一行怎麼改，不要拿去問他。** 他點頭再動手：

```bash
# Mac

```
```powershell
# Windows
Move-Item "[AGENT_HOME]" "[目標路徑]\[資料夾名]"
```

備援：`mv`／`Move-Item` 失敗（常見是雲端硬碟資料夾還在初始化）就請他用 Finder／檔案總管手動拖過去，拖完回來告訴你新路徑，你再往下做。

### B-3 改這台電腦的全域入口

搬完路徑變了，第 02 包留在 `~/.claude/CLAUDE.md`、`~/.codex/AGENTS.md`（或平台對應位置）裡指向 `core-rules.md` 的那一行要跟著改成新路徑。**直接改，不用問他**，改完講一句為什麼：

> 我把全域入口那一行改成新路徑了——**那一行就是「我家搬到哪」的門牌**，不改的話，你在別的資料夾開對話，我會找不到你是誰。

做法照第 02 包的寫法，只是把路徑換成搬家後的新路徑。

備援：改不動就把新路徑印給他，請他自己把那一行改掉，並確認一次「改完之後這一行長怎樣」。

## 踩坑紀錄（給 Tim）

- **放雲端硬碟一定要講「桌面同步版」不是「瀏覽器版」**——上傳到網頁版雲端硬碟只是備份一份，本機路徑不會同步，另一台電腦照樣找不到。
- **搬資料夾是這九包裡少數真正的破壞性操作**，一定要走「先列計畫、他點頭才動」，而且是整個搬移不是複製，複製會留兩份之後互相打架。
- **`core-rules.md` 那條接續規矩要先改再讓他刪 `tt-script.md`**，順序反了，刪掉腳本後那條規矩會指向一個不存在的檔案，下次想重跑就卡住。
- **onboarding.md 回傳只問一次。** 這是整堂課唯一一次主動要學員的資料，問一次不給就算了，不要用「這對你也有幫助」這種話術追問。
- **「兩台電腦不要同時開工同一專案」只用講的，不特別寫成強制規則**——寫成規則檔反而增加他每次都要讀的負擔，`handoff.md` 的「最後更新」欄位已經足夠讓他自己判斷。

## 常見問題

- **「我沒有在用雲端硬碟怎麼辦？」** 選 Q1 的「先了解原理」，這次不搬，資料夾留在原地一樣能用，之後真的要跨電腦再回來做。
- **「搬家會不會東西不見？」** 不會，整個資料夾原地搬過去，Section E 全綠才代表搬好；搬之前什麼都不刪。
- **「另一台電腦要重新跑九包嗎？」** 不用，只要重做第 02 包的兩個入口，其他規矩都跟著資料夾走。
- **`tt-script.md` 真的可以刪嗎？** 可以，它只是腳本，刪了不影響已經寫進 `core-rules.md` 的規矩。
- **「傳出去的 `onboarding.md` 會不會洩漏我的規矩？」** 不會，只傳這一份進度表，你的訪談答案都在 `core-rules.md`，那份不會傳出去。
