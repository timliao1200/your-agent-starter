# 收工寫日誌

## 什麼時候用
- 他說「收工」「今天先這樣」「下班」「幫我記一下」「寫 log」
- 一段工作告一段落、他要離開，而今天的日誌還沒寫或還沒更新

## 步驟

1. **先盤點**：從這段對話整理今天做了什麼、決定了什麼、還沒做完的。
2. **三個問題，一次問一個**，等他回答再問下一個：
   - 今天學到什麼？（一到三件，用他自己的話）
   - 卡在哪？（不順、沒懂、做到一半的；沒有就寫「沒有」）
   - 回去要做什麼？（明天或這週要試的一件事）
3. **寫檔** `memory/daily/YYYY-MM-DD.md`（台北時間；凌晨 0–4 點算前一天）。今天已經有檔就**更新同一份**，不要開第二份。格式：

   ```markdown
   # YYYY-MM-DD

   ## 主題
   一句話說明今天在做什麼

   ## 做了什麼
   - 寫結果，不寫過程

   ## 學到什麼
   - 他的話

   ## 卡在哪
   - …

   ## 明天要接的
   - …

   ## 他說的話
   > 逐字保留兩三句，不改寫

   工具：Codex／Claude Code、其他
   ```

4. **給他看一眼**，問「這樣可以嗎？要改哪裡？」改到他點頭。
5. **順手看 `memory/MEMORY.md`**：「最近在忙什麼」加一行，舊的擠掉；`updated` 改成今天。`memory/todo.md` 做完的移走。
6. **問要不要傳一份給老師**：「這篇要傳給老師嗎？可以選公開、匿名、只給老師，或不傳。」
   他要傳，就照這份流程做：`https://joylearnos.tierliao.workers.dev/shared/share.md`（把剛寫好的日誌內容傳上去，不要重新問一次三個問題）。
   他不傳，就到此為止。
7. 回一句：「日誌寫在 `memory/daily/YYYY-MM-DD.md`，[有／沒有]傳給老師。」不要展開。

## 不要做的事
- 不要在他沒說的情況下捏造內容
- 不要把整段對話貼進日誌，寫結果
- 不要每次都重新問報名 email；平台的登入資訊在 `.joylearn/token`，有就直接用
```

**跟他說一聲檔案在哪、裡面的第一行是什麼**：

> 招式建好了，在 `skills/daily-log/SKILL.md`。
>
> 你打開看最上面那幾行——**`description` 那段就是觸發條件**：什麼時候該用這一招。我看到情況對得上，就會自己去讀下面的步驟。

備援：寫檔工具不通就換一種方式建（純文字寫入也行），不要叫他去終端機打。

## 踩坑紀錄（給 Tim）

- **「觸發在規矩、程序在招式」這句一定要講出口。** 只給他一個招式檔，他學不到判斷；下次他還是把整套流程往規則檔塞。
- **當場測「收工」不能省。** 招式的價值在「他沒教你要問什麼，你自己去讀」，沒當場演一次，他只會覺得又多一個檔案。
- **同一天不要開第二份日誌、稍早傳過就別再問傳不傳。** 一天問兩次會讓人覺得這招很煩，招式再好也會被關掉。
- **刪「每天收工前」那節要精準。** 同一個 `tt:kit-03` 標記裡還有上工那幾條跟待辦維護，整塊蓋掉的話，下次開工就接不回進度。
- **語音那段就算他選「先跳過」也要寫進規矩。** 規矩不花他時間，哪天他開了語音就直接生效，不用回來重跑一包。

## 常見問題

- **「招式跟規矩到底差在哪？」** 規矩我每次開場都全部讀，所以只能放短的；招式是情況對了才讀，程序都放那裡。一句話：規矩寫「什麼時候」，招式寫「怎麼做」。
- **「我要自己記得叫它跑嗎？」** 不用。你說「收工」「今天先這樣」「下班」它就認出來了。真的沒動，你補一句「寫 log」也行。
- **「招式可以改嗎？」** 可以，那是純文字檔。想多問一題、想換檔名格式，直接改 `SKILL.md`，下次就照新的跑。
- **「我第二招想不到怎麼辦？」** 不用急。這幾天只要出現「怎麼又來了」的感覺，那件事就是候選，跟我說一聲我們再包。
- **「語音一定要開嗎？」** 不用。規矩寫好了放著，你哪天想用再開，不影響其他東西。
