> tt 是 Tim 派到你電腦裡的駐點 Agent 工程師。這一包做完，你會開第一間辦公室——一個資料夾、一份專案規矩、一份交接檔，換人換電腦都接得上。

## 你可能遇過的問題

- 好幾個案子的背景全部混在同一個對話裡，AI 常常把不同案子的東西搞混
- 想找一個熟悉某個案子的人幫忙，結果自己得先花十分鐘重講一次背景才能開始
- 案子做到一半要交給別人（或別的工具）接手，對方要摸半天才搞懂做到哪、下一步是什麼

## 做完你會有

- `projects/<name>/` 資料夾，裡面住著你的第一個專案員工
- `AGENTS.md`（本尊）＋ `CLAUDE.md`（一行入口）：這個案子自己的規矩，疊在你的全域規矩上面
- `handoff.md`：這個案子做到哪、下一步是什麼——換一台電腦、換一個 Agent，先讀這份就能接著做
- 用「先列計畫、你看過再動手」的方式做完的第一件事，而且交接檔已經照結果更新過

## Section A · 訪談（全部選擇題）

**選項題的格式**（每題都照這個）：
- `RUNTIME=claude` → 用 AskUserQuestion；其他 → 純文字列「1. 2. 3.」，結尾寫「回我數字，或直接打字也可以」
- 每題 ≤ 4 個選項，**推薦的放第一個並標（推薦）**，每個選項後面一句「選了會發生什麼」
- 最後一個選項永遠是「其他（我自己說）」
- 「要繼續嗎」一律兩個選項：「繼續（推薦）／先到這裡，下次再說」
- **他答完給一句短回應再往下**（「好，那這間辦公室就叫 `blog`」「懂了，原檔我留在原位，只複製一份進來」），一句就好，不要展開；他的答案要真的被用進你等一下寫的檔案裡

**A-1（只有沒素材才問）** — header：這次要開哪個辦公室
question：我要幫你開第一間辦公室，裝的是你真的想交給我做的東西。你想先用哪個？

1. **用一份我自己的文件**（推薦）——貼路徑給我，或直接把檔案拖進對話
2. **先跳過，第三堂再做**——這一包先停在這裡，下次上課再繼續
3. 其他（我自己說）——講給我聽是什麼案子

選 2 的話：跟他說一句「沒問題，這一包先停這裡」，在 `onboarding.md` 的「卡住的地方」記一行「08 包還沒帶素材，等第三堂再做」，**08 那行不打勾**，直接結束這一包，不要往下跑 Section B。

**A-2（拿到素材才問）** — header：辦公室取什麼名字
question：這個案子取一個英文資料夾名字，之後找它比較快。

1. **我幫你取**（推薦）——用案子性質抓一個英文詞，例如 `blog`、`taxes`、`client-a`，取完唸給你聽
2. **我自己說**——你直接講，我照你說的用

## Section B · 動手

### B-1 開辦公室

**直接開，不要問他「這樣建可以嗎」**——他沒看過辦公室長什麼樣，答不出來。邊建邊講：

> 我幫你開第一間辦公室。裡面放你帶來的東西，加上兩份小檔案——一份是這個案子的規矩（我是誰、這案子要做成什麼），一份是交接紀錄（做到哪、下一步是什麼）。
> **為什麼要分成一間一間**：案子各自有自己的背景，混在同一個對話裡我會搞混；分開之後，你回到哪個資料夾，我就自動變成那個案子的員工。

在 `[AGENT_HOME]` 底下建：

```
projects/<name>/
├── AGENTS.md      ← 這個案子的規矩（本尊；Codex 讀）
├── CLAUDE.md      ← 一行 @AGENTS.md（Claude Code 讀）
├── handoff.md     ← 交接：做到哪、下一步、注意事項
└── （他帶來的檔案）
```

**Mac**
```bash
mkdir -p "[AGENT_HOME]/projects/<name>"
```
**Windows（PowerShell）**
```powershell
New-Item -ItemType Directory -Force -Path "[AGENT_HOME]\projects\<name>"
```

他帶來的檔案（貼的路徑或拖進來的）複製或搬進這個資料夾——問他一句「原檔要保留在原位還是搬過來就好」，照他說的做。

備援：資料夾建不起來就用他自己的檔案總管／Finder 手動建，一次講清楚路徑跟資料夾名，請他建完回來說一聲。

### B-2 讓他理解交接檔在幹嘛

> 日誌記的是**你這個人**每天發生什麼；交接檔記的是**這個案子**做到哪、下一步是什麼。
> 兩個都要——換一台電腦、換一個 Agent 接手，先讀交接檔就能繼續，不用你再講一次背景。

### B-3 讓它做第一件事

先講清楚做法：

> 接下來我要幫你做第一件事。**這件事是你的案子，會動到你帶來的東西，所以我先把打算怎麼做列給你看一眼**——你不用懂我技術上怎麼弄，只要看方向對不對。

列出：目標一句話、打算怎麼做（編號步驟）、會動到哪些檔案。等他點頭（選項：「開始做（推薦）／方向要改一下」）再動手。

**這是這一包唯一一個要停下來的地方**——因為它動到他的原始素材。前面開資料夾、寫三份檔案那些不要問，直接做。

做完的結果整理給他看，然後把 `handoff.md` 更新成做完之後的狀態（見 Section C）。

備援：計畫他不點頭、要改方向，就照他說的重列一次，不要硬做原計畫。

## 踩坑紀錄（給 Tim）

- **這一包是骨架版**，內容深度先跟第三堂課現場對齊，之後照課堂反饋補齊細節（尤其是「素材長什麼樣」的例子，現場帶的東西比想像中雜）。
- **沒有素材就不要硬做。** 這一包的重點是讓他親手經歷「一個案子=一個資料夾」，用湊出來的假案例做，他記不住為什麼要這樣分。
- **交接檔是收工整份重寫，不是往下堆。** 這條規則要在 handoff.md 建立當下就講清楚，不然三個月後那份檔案會變成另一份看不完的日誌。
- **`AGENTS.md` 第一行一定要指回 `../../core-rules.md`。** 少了這行，這個專案員工就不認得他是誰，等於重新從零介紹一次。

## 常見問題

- **「素材一定要是完整文件嗎？」** 不用，一段流程描述、一張表格、甚至一句話講清楚要做什麼都算，重點是「真的要做的事」而不是練習用的假案例。
- **「一個案子可以有好幾個資料夾嗎？」** 不用，一個案子一個 `projects/<name>/`，裡面再分子資料夾放檔案就好。
- **「規矩要寫多細？」** 先求有，不求全——目標、限制、資料夾放法三段先寫出來，之後做的過程中發現該補的再補。
- **「這個案子的 `CLAUDE.md` 跟全域的 `CLAUDE.md` 會不會打架？」** 不會，Claude Code 會兩份疊著讀，專案那份只補案子細節，全域那份還是先讀。
