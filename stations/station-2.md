# 第 4 段 · 讓它記得

**這一段的目標**——開場講給他聽：

> 這一段你會知道**一件很多人搞錯的事**：AI 的「記憶」根本不在 AI 身上，在你的硬碟裡。
>
> 搞懂它怎麼運作，你就會知道**為什麼不能把所有東西都塞進規則檔**。

## 4-1 先讓他看見問題

> 有件事你可能還沒發現：**我們今天講的這些，你關掉對話我就忘了。**
>
> 你明天開新對話問我「昨天做到哪」，我會答不出來。因為對話框是有邊界的——**關掉就沒了**。
>
> 接下來我幫你把記憶從對話裡搬到檔案裡。

## 4-2 先講清楚：我有三種記憶

**這是整段的核心觀念，講完他才知道後面在幹嘛。**

> 先講一件事——**我不是「學會」你的事，我是每次上工重讀一次。**
>
> 模型本身不會為你改變。會改變的是**你硬碟裡的檔案**，我每次開工先讀一遍。
> 所以你的記憶是你的，換工具、換電腦，帶著資料夾走就好。

然後給他這張表：

> | | 放什麼 | 什麼時候讀 |
> |---|---|---|
> | **規矩** | 我該怎麼跟你做事 | 每次開場，**全部讀** |
> | **日記** | 那天發生了什麼 | 每次開場，**只讀最近幾天** |
> | **知識** | 你教過我的事 | **要用才查** |
>
> 記法就看右邊那欄：**全部讀 ／ 讀最近 ／ 要用才查。**

**然後講那句最關鍵的因果**——這決定他之後會不會把規則檔養成怪物：

> 重點在第一列：**「規矩」每次都全部讀進來。**
>
> 所以它不能一直長大。你把三百頁的資料都塞進規則檔，我每次開工都要先讀完那三百頁——
> **變慢、變貴，而且重點會被淹掉。**
>
> 這就是為什麼要有第三層。**知識放在外面，要用的時候才查。**
> 第五段我們就是在做那一層。

*（想查資料的話，這三種在學術上叫 procedural / episodic / semantic memory。）*

**還有一種不算記憶，但同一個道理**：

> `workflows/` 裡的流程也是「要用才讀」。
>
> 規則檔只寫一行索引說「流程在 workflows/」，內容留在外面。
> **這個模式你會一直看到：規則檔只記東西放哪，不記東西本身。**

## 4-3 建資料夾

> 剛才那三種記憶，現在變成資料夾：
>
> - **memory** — 「日記」那層。每天的日誌、摘要、待辦
> - **knowledge** — 「知識」那層。整理過的知識，這是你的第二大腦
> - **raw** — 原始素材，你丟進來不用整理。**知識的原料**
>
> 「規矩」那層不用建——就是 `core-rules.md`，第一站就寫好了。
> 另外順手建一個 `workflows/`——你叫它才跑的流程放這裡，第三站會用到。

還要再建一個，**這個要單獨講**：

> 最後一個叫 **projects**。
>
> 還記得第二段講的嗎——**你每多一個數位員工，就是多一個資料夾加一份專案規則檔。**
> 那些員工就住在這裡。
>
> 現在是空的。等你有第一個真的要交給它做的案子，我們就在裡面開第一間辦公室。

`projects/README.md` 要寫清楚，不要讓它變成一個看不懂的空資料夾：

```markdown
# projects/

每一個子資料夾 = 一個專案員工。

裡面放一份 `CLAUDE.md`（這個案子的規矩）＋ 這個案子的檔案與產出。
它會自動疊上你的全域規則檔——所以它認得你，同時懂這個案子。

還沒有任何專案。跟我說「幫我開一個 XX 的員工」就會建。
```

在 `AGENT_HOME` 底下建立：

```
memory/
memory/daily/
knowledge/
raw/
projects/
skills/
workflows/
```

`skills/` 先建空的加一份 `README.md` 就好——**那是之後的事**，
但位置先留著，他才知道招式要往哪放。

（`workflows/` 已經有的話不用重建。）

**每個空資料夾放一個 `README.md`**，兩三句話說明放什麼、舉一個例子。空資料夾會讓人不知道要幹嘛。

## 4-4 日記那層裡面又分三個檔

**先講關係，再建檔案。**

> 剛才說的「日記」那層，打開來看是三個檔案：
>
> - **日誌**（`memory/daily/`）— 每天發生的事，會一直累積。一年後有三百多篇，**沒有人會全部讀完，我也不會**
> - **摘要**（`memory/MEMORY.md`）— 那三百篇的精華。**這是我每次上工唯一一定會讀的**
> - **待辦**（`memory/todo.md`）— 現在要做什麼
>
> 關鍵在中間那層：**摘要如果過期了，我對你的認識就停在那一天**——底下的日誌記得再完整，也到不了我面前。

> 最多三件。

- **怎麼檢查**：每次讀的時候看 `updated`。超過一週沒動就是壞了——當場用日誌補到最新，並告訴你一聲

## 4-6 把規則寫進規則檔

在 `RULE_FILE` 補上：

```markdown
## 每次上工先做的事

1. 讀 `memory/MEMORY.md`——必讀，不能跳
2. **順手看最上面的 `updated` 日期**。超過一週沒更新，代表我對你的認識過期了：
   當場翻 `memory/daily/` 最近幾篇補上，然後告訴你一聲
3. 讀 `memory/todo.md`
4. 翻一下 `memory/daily/` 最近兩三天，接上進度

## 每天收工前

把今天做的事寫進 `memory/daily/YYYY-MM-DD.md`，四段：

- **主題**：一句話說明今天在做什麼
- **做了什麼**：寫**結果**，不要寫過程。包含我查到什麼、排除了什麼、動過哪些檔案
- **決定了什麼**：寫「決定了什麼」，不是「討論了什麼」。沒有就省略
- **明天要接的**：還沒做完的事

你今天講的話裡有特別有觀點的兩三句，逐字留下來不要改寫——那是你的聲音。

寫完順手檢查 `memory/MEMORY.md` 要不要跟著改。

## 待辦清單怎麼維護

- 看到 `[x]` 打勾的 → **從 todo.md 移走**，寫進當天的日誌。清單只留還沒做的事
- 他說「先緩緩」→ 改成 `[~]`，不要刪。緩不是放棄
```

**這一步不能省。** 給他完整路徑：

> **`[完整路徑]/memory/daily/[今天日期].md`**
>
> 你打開看一下——**那是一個純文字檔，你隨時可以自己讀、自己改**。

然後講一句最重要的：

>
> 哪天你換工具、換公司、換一個 AI 來用，把這個資料夾帶著走就好——**你的記憶不會被鎖在誰的伺服器裡。**

照這份流程做：`https://joylearnos.tierliao.workers.dev/shared/share.md`

# 第 7 段 · 給它工具

**這一段的目標**——開場講給他聽：

> 到目前為止，我會記事、會讀你的檔案。但你電腦上大部分的工作——Word、Excel、簡報、PDF——**我還沒有工具可以動它們。**
>
> 這一段幫我裝十個工具。裝完之後，你叫我「把這份名單套進通知單」「把這幾份 PDF 合併」，我就真的做得出檔案來，不是給你一段文字要你自己貼。
>
> 順便你會弄懂一件事：**為什麼 AI Agent 叫「代理」。**

## 7-1 先講清楚：我有四隻手腳

> 以前你用的 AI 只會動嘴——不管問什麼，它都只能回你文字。
>
> 我不一樣，我住在你電腦裡，所以我有手腳。我能做的事分四種：
>
> | | 一句話 |
> |---|---|
> | **讀** | 你電腦裡的檔案我看得到、改得動 |
> | **處理** | 我會寫程式、跑程式，缺工具自己裝 |
> | **抓** | 我能上網查、下載，抓的是現在的網 |
> | **產出** | 我直接給你成品檔：Word、Excel、簡報、PDF、圖 |
>
> 這四件事合起來，就是「代理」的意思——**你能做的我能做，你不能做的我也能做，因為我會用你不會用的程式。**
>
> 但有一條不變：**我做的是勞務，成品拿去用之前，最後一關永遠是你。**

**然後教他一個習慣，這是省錢的第一招：**

> 以後你要我看某個檔案，**不要把檔案拖進對話框，貼它的路徑給我。**
>
> Windows：在檔案上按右鍵 →「複製路徑」（或按 Ctrl＋Shift＋C）。
> Mac：在 Finder 選檔案，按 Option＋Cmd＋C。
>
> 為什麼？你沒告訴我東西在哪，我就要到處找，找的過程都在燒你的額度。
> 而且貼路徑我每次讀到的都是最新版，不會佔掉這段對話的記憶。**告訴我東西在哪，比把東西塞給我便宜。**

## 7-2 裝十個工具

**先跟他說一聲要動什麼，不要默默裝：**

> 我要在你的 `user-agent` 裡開一個 `tools/` 資料夾，把十個 Python 套件裝在裡面。
>
> 裝在這裡的好處：**只動這個資料夾，不會弄髒你電腦原本的 Python**；而且一台電腦裝一次，你之後不管用哪個 Agent 都能用。
>
> 過程中會跳出幾次「允許執行」，你按同意就好。**可以嗎？**

### 六條規則（照三師爸的做法，經過驗證）

1. **只在 `[AGENT_HOME]/tools/` 裡工作**，不要去搜別的磁碟、別的資料夾
2. **只裝核心的十個**，下面「選裝」那些不要自動裝，除非他明確點名
3. **不用全域 `pip install`**，一律裝進 `tools/.venv`
4. **不要逐項上網研究**，版本交給 `uv` 解析；不要為每個套件另開網頁或寫長篇計畫
5. **最多重試一次**。失敗就回報原始錯誤跟你的建議，不要反覆改指令、不要自己切成管理員
6. **不要自己換執行環境**。Windows、WSL、沙盒是不同的環境，不要為了裝而改用另一個

### 動手

先建 `[AGENT_HOME]/tools/requirements-core.txt`：

```
python-docx
openpyxl
python-pptx
pypdf
PyMuPDF
reportlab
Pillow
matplotlib
qrcode[pil]
markitdown[pdf,docx,pptx,xlsx]
```

**第一步：確認有沒有 `uv`**（一個很快的 Python 套件管理工具，沒有 Python 也能幫你裝）：

```bash
uv --version
```

沒有就裝：

- **Mac**：`curl -LsSf https://astral.sh/uv/install.sh | sh`（裝完關掉終端機重開，或執行 `source ~/.zshrc`）
- **Windows（PowerShell）**：`winget install --id astral-sh.uv -e`，或 `powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"`（裝完重開終端機）

**第二步：建環境、裝套件**（在 `[AGENT_HOME]` 底下執行）：

```bash
uv venv tools/.venv --python 3.12
uv pip install --python tools/.venv -r tools/requirements-core.txt
```

Windows 的 `--python` 路徑寫 `tools\.venv\Scripts\python.exe`；Mac 寫 `tools/.venv/bin/python`。`uv` 找不到 3.12 會自己下載，不用他做事。

**第三步：驗證**——建 `[AGENT_HOME]/tools/verify_core.py`：

```python
import importlib
mods = {"python-docx":"docx","openpyxl":"openpyxl","python-pptx":"pptx","pypdf":"pypdf",
        "PyMuPDF":"fitz","reportlab":"reportlab","Pillow":"PIL","matplotlib":"matplotlib",
        "qrcode":"qrcode","markitdown":"markitdown"}
ok = 0
for name, mod in mods.items():
    try:
        importlib.import_module(mod); print("ok  ", name); ok += 1
    except Exception as e:
        print("FAIL", name, "-", e)
print(f"{ok}/{len(mods)} 可用")
```

用 `tools/.venv` 的 Python 跑它。**十個都 ok 才算完成。** 有 FAIL 的，重試一次；還不行就記進 `onboarding.md` 的「卡住的地方」，繼續往下（缺一兩個不影響今天）。

### 備援：`uv` 真的裝不起來

用系統的 Python（Mac 通常有 `python3`；Windows 到 python.org 裝，勾 Add to PATH）：

```bash
python3 -m venv tools/.venv
tools/.venv/bin/python -m pip install -r tools/requirements-core.txt
```

Windows 把 `tools/.venv/bin/python` 換成 `tools\.venv\Scripts\python.exe`。

## 7-3 十個工具能做什麼——用他的工作講

## 5-1 先講方法論

> 接下來這套做法叫 **LLM Wiki**，是 Andrej Karpathy 提出來的——他是 OpenAI 創始成員、Tesla 前 AI 總監。
>
> 核心想法很簡單：**不要每次都叫 AI 去翻原始文件，而是讓它把讀過的東西整理成一個會長大的知識庫。**

三層講清楚：

> | 層 | 在哪 | 放什麼 | 誰動它 |
> |---|---|---|---|
> | **① 原料** | `raw/` | PDF、逐字稿、文章 | 你丟進來，**我只讀不改** |
> | **② 知識** | `knowledge/` | 我整理出來的知識，互相有連結 | 我寫、我維護 |
> | **③ 規格** | `knowledge/AGENTS.md` | **定義這個知識庫怎麼組織** | 你我一起維護 |

**第三層最容易被跳過，但少了它整套不會運轉**——一定要講：

> 第三層叫 **schema**，就是**知識庫自己的規則檔**。

> 它規定：一頁筆記長什麼樣、要有哪幾個區塊、什麼東西該建新頁什麼該併進舊頁、
> 多久沒動要標成過期。
>

**然後把它跟第二段扣起來**（他已經學過這個概念了）：

> 它會疊在 `core-rules.md` 上面：我在知識庫裡做事的時候，同時知道「你是誰」跟「這個知識庫怎麼維護」。

三個動作：

## 8-1 先講清楚：流程、招式、規矩差在哪

> 三種東西，放三個地方：

# 收工寫日誌

## 什麼時候用
- 他說「收工」「今天先這樣」「下班」「幫我記一下」「寫 log」
- 一段工作告一段落、他要離開，而今天的日誌還沒寫或還沒更新

## 步驟

1. **先盤點**：從這段對話整理今天做了什麼、決定了什麼、還沒做完的。
2. **三個問題，一次問一個**，等他回答再問下一個：
   - 今天學到什麼？（一到三件，用他自己的話）
   - 卡在哪？（不順、沒懂、做到一半的；沒有就寫「沒有」）
   - 回去要做什麼？（明天或這週要試的一件事）
3. **寫檔** `memory/daily/YYYY-MM-DD.md`（台北時間；凌晨 0–4 點算前一天）。今天已經有檔就**更新同一份**，不要開第二份。格式：

   ```markdown
   # YYYY-MM-DD

   ## 主題
   一句話說明今天在做什麼

   ## 做了什麼
   - 寫結果，不寫過程

   ## 學到什麼
   - 他的話

   ## 卡在哪
   - …

   ## 明天要接的
   - …

   ## 他說的話
   > 逐字保留兩三句，不改寫

   工具：Codex／Claude Code、其他
   ```

4. **給他看一眼**，問「這樣可以嗎？要改哪裡？」改到他點頭。
5. **順手看 `memory/MEMORY.md`**：「最近在忙什麼」加一行，舊的擠掉；`updated` 改成今天。`memory/todo.md` 做完的移走。
6. **問要不要傳一份給老師**：「這篇要傳給老師嗎？可以選公開、匿名、只給老師，或不傳。」
   他要傳，就照這份流程做：`https://joylearnos.tierliao.workers.dev/shared/share.md`（把剛寫好的日誌內容傳上去，不要重新問一次三個問題）。
   他不傳，就到此為止。
7. 回一句：「日誌寫在 `memory/daily/YYYY-MM-DD.md`，[有／沒有]傳給老師。」不要展開。

## 不要做的事
- 不要在他沒說的情況下捏造內容
- 不要把整段對話貼進日誌，寫結果
- 不要每次都重新問報名 email；平台的登入資訊在 `.joylearn/token`，有就直接用
```

**跟他說一聲檔案在哪、裡面的第一行是什麼**：

> 招式建好了，在 `skills/daily-log/SKILL.md`。
>
> 你打開看最上面那幾行——**`description` 那段就是觸發條件**：什麼時候該用這一招。我看到情況對得上，就會自己去讀下面的步驟。
