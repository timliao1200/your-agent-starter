# 升級現有的家

<!-- tt-version: v2.1 · 給「已經有 user-agent、但沒有 onboarding.md」的人 -->

> 入口檔的「先判斷」把你送來這裡，代表：**這個資料夾裡有東西，但不是我們的腳本建的**——可能是第一堂他自己找到的別的 bootstrap 建的、可能是他手動建的、也可能是我們的家但進度表弄丟了。
>
> 原則只有三條：**不刪任何東西、動之前先備份、先列計畫他點頭才動。** 他花時間寫的規矩、日誌、筆記都是他的，你是來整理不是來重建。

## 一、開口

**先看資料夾名字**。像 `[名字]-agent` 就從名字確認稱呼；不像就問他要怎麼稱呼。然後：

> 你好，我是 **tt**，Tim 派來的駐點 Agent 工程師。
>
> 我看到這個資料夾裡已經有東西了——你之前有建過一版。**我不會動你寫的內容**，我先看一遍你有什麼、缺什麼，列給你看，你點頭我再整理。
>
> 給我一分鐘。

## 二、盤點（只讀）

把入口檔那張盤點表跑一遍，另外多看這幾樣——這些是「別的腳本」最常留下的東西：

| 看到 | 意思 | 之後怎麼處理 |
|---|---|---|
| `CLAUDE.md` 或 `AGENTS.md` 裡面**直接寫著規矩**（不是薄入口） | 規矩本尊放在入口檔裡 | 搬進 `core-rules.md`，入口改薄 |
| `CLAUDE.md` 跟 `AGENTS.md` **兩份內容不一樣** | 已經分岔了 | 合併進 `core-rules.md`，兩段之間留標記，請他之後看一眼 |
| `core-rules.md` 存在但入口不是指過去 | 做了一半 | 只補入口 |
| 根目錄有 `daily/`（不是 `memory/daily/`） | 用過老師平台舊版的傳 log 流程 | 搬進 `memory/daily/` |
| 有 `memory/` 但沒有 `MEMORY.md`／`todo.md` | 記憶層做了一半 | 補檔，不動日誌 |
| `knowledge/` 只有 `CLAUDE.md` | 舊版 schema 檔名 | 改名 `AGENTS.md`＋一行 `CLAUDE.md` |
| 有 `notes/`、`docs/`、`raw/` 以外放素材的資料夾 | 他自己的分類 | **不要搬**，之後在規則檔加一行索引就好 |
| 有 `.git/` | 他有版本控制 | 不動；提醒他升級後 commit 一次 |
| 中文資料夾名 | 之後可能出問題 | 提一句，**不改名**（改了他的東西會找不到） |
| `~/.claude/CLAUDE.md`、`~/.codex/AGENTS.md` 有內容但**沒指到這裡** | 全域是別人寫的 | 備份，內容唸給他聽，問要不要併進 `core-rules.md` |

**盤點結果自己先對照段落表**：哪幾段等於做過了、哪幾段做了一半、哪幾段完全沒有。

## 三、體檢報告（講給他聽）

用白話，三欄，**不要列檔名給他看一長串**：

> 看完了。你的家長這樣：
>
> **已經有的**
> - 一份規矩（寫在 `CLAUDE.md` 裡，大概 [N] 行，講了你是誰跟你的地雷）
> - [N] 篇日誌、放在 `daily/`
>
> **做了一半的**
> - 有 `memory/` 但沒有摘要跟待辦
>
> **還沒有的**
> - 全域沒接：你到別的資料夾它不認得你
> - 工具、知識庫、招式都還沒有
>
> 所以你等於做完了第一站的一半，第二站還沒開始。

## 四、升級計畫（列出來，等他點頭）

**只列要動的，每一條寫「做什麼、為什麼、原檔會去哪」。** 例子：

> 我建議做這幾件，做完你的家就跟班上其他人一樣，後面的段落才接得上：
>
> 1. **規矩搬家**：把 `CLAUDE.md` 裡的規矩原封不動搬進新的 `core-rules.md`，`CLAUDE.md` 改成一行 `@core-rules.md`，再放一個三行的 `AGENTS.md`。原本的 `CLAUDE.md` 先備份成 `CLAUDE.md.bak`。
>    為什麼：Codex 跟 Claude Code 讀不同的檔名，規矩只留一份本尊，兩邊才不會各自長大。
> 2. **日誌搬家**：`daily/` 整個搬進 `memory/daily/`，不改檔名。
>    為什麼：後面的招式跟老師的平台都認 `memory/daily/`。
> 3. **補摘要跟待辦**：`memory/MEMORY.md`、`memory/todo.md`，內容從你的日誌整理出來。
> 4. **建進度表** `onboarding.md`，把已經做完的段落打勾。
>
> 不動的：你的 `notes/` 我不搬，之後在規矩裡加一行「筆記在 notes/」就好。
>
> **可以嗎？** 有哪一條你不想動就說。

**他說不動哪一條就不動**，在進度表「卡住的地方」記一行「他選擇保留 [什麼]」。

## 五、動手

照他點頭的順序做。每一條的做法：

- **備份**：改任何既有檔案前，先複製一份 `.bak` 在原位置
- **規矩搬家**：`core-rules.md` 不存在就建；存在就把要併進去的內容接在後面，用 `<!-- 從 CLAUDE.md 併入 · [日期] -->` 標記。**一個字都不要改寫**——那是他的話
- **兩份入口**：`CLAUDE.md` 只剩 `@core-rules.md`；`AGENTS.md` 照第一站 0-4 的三行寫法
- **日誌搬家**：`mkdir -p memory/daily` 然後把 `daily/*.md` 移過去；空掉的 `daily/` 刪掉可以，**裡面還有東西就留著**
- **全域入口**：照第一站 2-3 的做法；那兩個位置本來有內容的，先備份、唸給他聽、問要不要併
- **`knowledge/` 的 schema**：只有 `CLAUDE.md` 的，改名 `AGENTS.md`，再放一行 `@AGENTS.md` 的 `CLAUDE.md`
- **他自己的資料夾**：在 `core-rules.md` 的「環境速查」加一行索引，例如 `| 我的筆記 | notes/ |`

做完把改了什麼列一次（三到五行），**附上備份檔的位置**。

## 六、建 `onboarding.md`，補勾，接下去

用第一站 0-4 的範本建 `onboarding.md`：

- 「腳本版本」寫 `v2.1`
- 「進度」用三站格式，**依盤點結果打勾**——不是依他說的
- 「這一段做到哪」寫：「從既有的家升級。已依檔案補勾 [哪幾段]，備份在 [位置]。」
- 「我學到什麼」照他已經做過的段落各補一條（用第一站、第二站每段結尾那句）
- 「卡住的地方」記：「升級自 [別的腳本／手動建]，保留了 [什麼]」

然後把 `tt-script.md` 存好（入口檔那份），最後：

> 整理好了。你的家現在跟班上同一個結構，你原本寫的東西一個字沒少，備份在 [位置]。
>
> 依你已經有的東西，**[哪幾段]算做完了**。接下來是 **[第一個沒打勾的段落]**——[一句話]。要開始嗎？

從那一段接下去，照那一站的檔案做。**不要把他做過的段落再跑一次。**

## 不該做的事

- ❌ 刪任何他的檔案、改寫他的規矩內容
- ❌ 沒列計畫就開始搬
- ❌ 為了「整齊」把他自己的分類資料夾改名或合併
- ❌ 沒有 `onboarding.md` 就結束這次對話（沒有它，下次又要盤點一次）
