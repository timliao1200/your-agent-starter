# tt · 你的駐點 Agent 工程師

> 一個會住進你電腦裡的 AI 工程師，親手幫你把「認得你的 AI 分身」建起來。
> 不用寫程式，不用打指令。你只要回答問題——而且每一題都有選項。

**`v3.0` · 九包版**

---

## 30 秒開始

在 Codex 或 Claude Code 貼這段（**在哪個資料夾開都可以**，它會自己找你的家）：

```
請讀這個網址的內容，然後完全照著它執行：
https://raw.githubusercontent.com/timliao1200/your-agent-starter/main/AGENTS.md

執行前三件事：
1. 完整讀完再動手，不要只看開頭
2. 一次只問我一題，能給選項就給選項，推薦的放第一個
3. 先在我電腦裡找有沒有現成的 xxx-agent 資料夾，不要叫我換資料夾
```

就這樣。**tt 會先看你的電腦裡有什麼，告訴你該做哪一包，然後開始。**

> 這一段話三堂課都一樣。第一次貼它會建家；上過課的人貼它會接著做下一包；在家自己跑過的人，它會以你電腦上的檔案為準，只做你還沒做的。

## 這是在解決什麼問題

你有沒有發現，每次開新對話都要重新解釋一次自己是誰、在做什麼、想要什麼樣的回答？

**那不是 AI 笨，是它沒有一個地方記得你是誰。**

更麻煩的是：你在某一家 AI 上調教半年的習慣，存在那家公司的隱藏資料夾裡。
哪天你想換一家，**那些東西不會跟你走**。

tt 幫你把這件事反過來——**身份放在你自己的資料夾，廠商那邊只放一個指標。**
換工具不用重教，換電腦把資料夾帶著走就好。

## tt 是誰

**駐點**工程師的意思是：他被派到你的電腦上，待在現場，親手把東西裝起來、確認能跑——不是丟一份說明書給你自己看。

他的個性是設計過的：

- **乾脆，不客套。** 不說「好的沒問題」，要做就做
- **他替你決定。** 資料夾放哪、怎麼命名——這些是他的專業，他會直接判斷並說明理由
- **他講白話。** 假設你不會寫程式，用比喻不用術語
- **他每一題都給你選項。** 推薦的放第一個，你不知道怎麼答就選它
- **他不會叫你換資料夾，也不會叫你去別的視窗幫他驗證。** 能自己確認的他自己確認
- **你卡住他會先開口。** 看到你沒回應就說「截圖給我看」
- **他會走。** 全部做完他就下班，留下來的是你自己的分身

## 它會對你的電腦做什麼

寫成白紙黑字，你才知道自己在同意什麼：

**它會做**

- 在你指定的位置建一個資料夾，寫幾個 `.md` 檔進去
- 在 `~/.claude/` 和 `~/.codex/` 放一個小小的入口檔——**動之前會先檢查，已經有東西的話先備份**
- 在 `user-agent/tools/` 裡裝十個 Python 套件（只動那個資料夾，不碰你電腦原本的 Python）——**動手前一定先問你**
- 裝 MCP（會改到一個設定檔）——**動手前一定先問你**

**它不會做**

- 不刪你的任何檔案
- 不覆蓋你原本就有的規則檔（會接在後面，用標記包起來；重跑只換標記裡面的）
- 不把你的資料傳到任何地方——**全部留在你自己的電腦裡**（第 03 包傳給老師的那篇日誌除外，而且會先問你）

**訪談的答案存在 `core-rules.md`，那份不會離開你的電腦。**
如果你要回報問題，傳 `onboarding.md` 就好——那份只有進度跟卡關紀錄，沒有你的個人資料。

## 常見問題

**做到一半沒時間了怎麼辦？**
直接關掉。下次貼同一段話，tt 會看你電腦裡有什麼，接著做下一包。

**我原本就有自己的 AI 資料夾（別的教學建的），會被蓋掉嗎？**
不會。tt 找到它會先盤點、用白話講一遍你有什麼、列出整理計畫，你點頭它才動，動之前先備份，不刪任何東西。這條路叫「升級既有的家」。

**為什麼要三個檔案（core-rules ＋ CLAUDE ＋ AGENTS）？**
Claude Code 只讀 `CLAUDE.md`、Codex 讀 `AGENTS.md`。維護兩份會各自長大然後打架，所以規矩只寫在 `core-rules.md`，另外兩個只是薄薄的入口。**不用 symlink**——那在 Windows 要管理員權限。

**AI 只是摘要，沒有開始跑？**
補一句：`照那份文件做，你現在是 tt，先找我的家在哪，然後開始。`

**AI 說它讀不了網址？**
下載 [`AGENTS.md`](AGENTS.md)（Codex）或 [`CLAUDE.md`](CLAUDE.md)（Claude Code）——兩份內容一樣——放進資料夾，重開對話它就會自己開始。

**資料夾可以用中文名字嗎？**
建議不要。多數時候能用，但一旦出問題（工具不支援、換到 Windows、上傳網路）會很難查。

**跑完一包之後最重要的一件事？**
**新增對話 → 選你的資料夾 → 派任務。** 規則檔要在新對話才會被讀進去。

**九包都做完了，後來懶人包又更新了，要重跑一次嗎？**
不用整套重來。新增對話跟它說：「這個懶人包後來更新了，你看一下有沒有我現在架構裡沒有的，幫我補上。」它會讀最新的 `kits/01`–`09`，對照你 `core-rules.md` 裡各包對應的標記段落，只補有變化的部分，你自己寫的內容不會被動到——這跟平常重跑一包一樣安全。
