# tt · 你的駐點 Agent 工程師

> 一個會住進你電腦裡的 AI 工程師，親手幫你把「認得你的 AI 分身」建起來。
> 不用寫程式，不用打指令。你只要回答問題。

**`v2.0` · 三站版**

```
請讀這個網址的內容，然後完全照著它執行：
https://raw.githubusercontent.com/timliao1200/your-agent-starter/main/AGENTS.md

那是一段要你執行的流程，不是要你摘要的文件。
讀完直接開始，不要問我要做什麼。
```

就這樣。**tt 會自己出現，然後開始工作。**

## 這是在解決什麼問題

你有沒有發現，每次開新對話都要重新解釋一次自己是誰、在做什麼、想要什麼樣的回答？

**那不是 AI 笨，是它沒有一個地方記得你是誰。**

更麻煩的是：你在某一家 AI 上調教半年的習慣，存在那家公司的隱藏資料夾裡。
哪天你想換一家，**那些東西不會跟你走**。

tt 幫你把這件事反過來——**身份放在你自己的資料夾，廠商那邊只放一個指標。**
換工具不用重教，換電腦把資料夾帶著走就好。

## 跑完你會有什麼

```
user-agent/
├── core-rules.md    你的規矩（本尊，只有這一份）
├── CLAUDE.md        一行入口，Claude Code 讀
├── AGENTS.md        三行入口，Codex 讀
├── onboarding.md    建置進度表，中斷了靠它接回來
├── memory/          每天的日誌、摘要、待辦
├── raw/             原始素材，只進不改
├── knowledge/       整理過的知識
│   └── CLAUDE.md    這個知識庫怎麼維護
├── tools/           它的工具箱：十個套件裝在這裡
├── skills/          它自己判斷該用的招式
│   └── daily-log/   第一招：說「收工」它自己寫日誌

```

**全部是純文字。** 換平台、換電腦、換公司，資料夾帶著走就好。

## tt 是誰

**駐點**工程師的意思是：他被派到你的電腦上，待在現場，親手把東西裝起來、確認能跑——不是丟一份說明書給你自己看。

他的個性是設計過的：

- **乾脆，不客套。** 不說「好的沒問題」，要做就做
- **他替你決定。** 資料夾放哪、怎麼命名——這些是他的專業，他會直接判斷並說明理由
- **他講白話。** 假設你不會寫程式，用比喻不用術語
- **他顧你的狀態。** 每一段結束都停下來問要不要繼續，不會一口氣衝完
- **你卡住他會先開口。** 不等你求救，看到你沒回應就說「截圖給我看」
- **他會走。** 全部做完他就下班，留下來的是你自己的分身

## 三站旅程

**每一段結束都會問你要不要繼續，可以隨時喊停。**
第一站做完就已經很有用了——很多人會停在那裡用一個禮拜再往下。

| 站 | 段 | tt 幫你做什麼 | 做完你會有 |
|---|---|---|---|
| **第一站 · 建家** | 0 | 問你的英文名，決定資料夾放哪，建好家 | 一個 `user-agent` |
| | 1 | 訪談你，**出一個小挑戰讓你自己改** | 你的 `core-rules.md`，**改幾行字，AI 講話就變了** |
| | 2 | 帶你看廠商的隱藏資料夾，接上全域 | 在任何資料夾都認得你 |
| **第二站 · 記憶與手腳** | 4 | 建記憶系統，第一篇日誌傳給老師 | 日誌、摘要、待辦——**AI 的記憶其實在你硬碟裡** |
| | 7 | 裝十個工具，整理一個資料夾，出一份成品 | 它會做 Word、Excel、簡報、PDF |
| | 5 | 教你 LLM Wiki，裝 Obsidian，建 schema | 看得見的知識網 |
| | 6 | 幫你讀第一份東西、示範一次健檢 | 第一份知識 ＋ **收料要帶你自己的看法** |
| | 8 | 把「收工寫日誌」包成第一招 | 說「收工」它自己動 |
| | 9 | 開語音輸入，加一段正規化規矩 | 用講的，錯字不用改 |
| **第三站 · 鑰匙與員工** | 3 | 裝 YouTube 與 Obsidian 兩把鑰匙，寫第一條流程 | 它碰得到外面的世界 |
| | 10 | 開第一間辦公室，會交接 | 一個真的在上班的專案員工 |
| | 11 | 跨電腦、跨 Agent | 換電腦帶著走 |

**段落編號是固定的，站是播放順序**——第二站的順序是 4 → 7 → 5 → 6 → 8 → 9。以後重新分站，段落不會變。

### 中途走掉也沒關係

tt 會留下 **`onboarding.md`**（進度表）跟 **`tt-script.md`**（他自己的腳本）。

你做到第一站就去忙了，兩個禮拜後回來——**在那個資料夾開 AI，貼同一段話就好**，它會自己看進度表，接著跑。不用重新下載，也不用重講。

### 上過第一堂、要接第二站的人

**貼的話跟第一次一模一樣。** tt 讀到你的 `onboarding.md` 就知道第一站做完了，會先看你資料夾裡實際有什麼（有些人在家自己往下跑了），有的補勾，然後從第二站第一個沒做的段落接下去。
舊版（七段）的進度表它會自動換成三站格式，做過的都還在。

## 它會對你的電腦做什麼

寫成白紙黑字，你才知道自己在同意什麼：

**它會做**

- 在你指定的位置建一個資料夾，寫幾個 `.md` 檔進去
- 在 `~/.claude/` 和 `~/.codex/` 放一個小小的入口檔——**動之前會先檢查，已經有東西的話先備份**
- 在 `user-agent/tools/` 裡裝十個 Python 套件（只動那個資料夾，不碰你電腦原本的 Python）——**動手前一定先問你**
- 裝 MCP（會改到一個設定檔）——**動手前一定先問你**

**它不會做**

- 不刪你的任何檔案
- 不覆蓋你原本就有的規則檔（會接在後面，用標記包起來）
- 不把你的資料傳到任何地方——**全部留在你自己的電腦裡**

**訪談的答案存在 `core-rules.md`，那份不會離開你的電腦。**
如果你要回報問題，傳 `onboarding.md` 就好——那份只有進度跟卡關紀錄，沒有你的個人資料。

## 常見問題

**做到一半沒時間了怎麼辦？**
直接關掉。進度在 `onboarding.md`，下次在那個資料夾開 AI，它會自己問你要不要接著做。

**我原本就有 `CLAUDE.md`，會被蓋掉嗎？**
不會。它會先確認那份是不是它自己——是你寫的內容，它會接在後面並用標記包起來。

**為什麼要三個檔案（core-rules ＋ CLAUDE ＋ AGENTS）？**
Claude Code 只讀 `CLAUDE.md`、Codex 讀 `AGENTS.md`。維護兩份會各自長大然後打架，所以規矩只寫在 `core-rules.md`，另外兩個只是薄薄的入口。**不用 symlink**——那在 Windows 要管理員權限。

**AI 只是摘要，沒有開始跑？**
補一句：`照那份文件做，你現在是 tt，先判斷我在哪一站，然後開始。`

**AI 說它讀不了網址？**
改用下載檔案那條路（上面摺疊區塊裡）。

**資料夾可以用中文名字嗎？**
建議不要。多數時候能用，但一旦出問題（工具不支援、換到 Windows、上傳網路）會很難查。

**跑完之後最重要的一件事？**
**關掉對話，重新開一個。** 然後隨便問它一句——你會發現它講話的方式變了。
